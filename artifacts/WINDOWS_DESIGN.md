# Windows 首轮技术设计

## 范围

首个客户端采用 Flutter Windows 和 Material Design 3，本机 Python 3.12 网关负责 AKShare 和 SQLite。暂以历史回放为开发假设，产品范围仍待确认。既有探测取得过深市腾讯和新浪日线、沪市腾讯日线、深市新浪分钟线。沪市腾讯日线曾复测超时，全市场快照、实时能力和完整分钟覆盖仍待验证。

首个界面里程碑是股票搜索、自选和日线／分钟行情浏览。交易里程碑增加回放时钟、限价委托与撤单、持仓、成交、流水和资产曲线。行情页显示行情时间、来源、刷新失败、缓存和覆盖状态。宽窗口使用侧栏和列表／详情，窄窗口保留可操作的单栏导航。

## 数据与领域边界

- 行情网关返回版本化 JSON。SQLite 缓存按完整查询键保存最近一次成功快照。一次快照只含一个数据源，缓存回退显式返回抓取时间和原因。
- 日线用交易日标识，分钟用带 +08:00 的源时间戳。价格和金额用十进制字符串，数量以股为单位。成交量转换按适配器口径处理。保留上游精度，撮合所需的价格最小变动单位由规则层独立校验。
- 行情浏览可展示不完整日。连续竞价分钟覆盖检查按标签 09:31–11:30、13:01–14:57 计算，单独报告 15:00 标签。实际标签与事件时刻映射需验证后才能进入撮合。
- Python 网关仅负责数据。Dart 交易域持有回放时钟、订单、成交、持仓批次和现金账本。界面只能通过应用层读取按回放时钟裁剪的数据，回放期间日线也要等完整收盘事件才可见。

订单通过规则检查后冻结现金（含费用上界）或可卖持仓。候选撮合模型以严格晚于委托的下一合格分钟开盘事件检查限价和成交量，零量时跳过，无法按整体数量成交时等待。它无法重建真实队列、分钟内路径和市场冲击。成交、订单状态、现金和持仓在一次事务中提交，由事件标识约束幂等。撤单或到期释放剩余冻结。买入新增按交易日记录的持仓批次，卖出扣减冻结批次。

## 阶段与验收

1. Windows 本机网关。补测沪深代表股票、目录、日历和停复牌源。验收上游超时、限流、显式缓存回退、数据校验、缺失分钟和无数据。
2. Dart 交易引擎。补齐有日期版本的规则和历史状态证据后接入撮合。验收无未来数据、资金守恒、撤单解冻、重复事件和恢复一致性。
3. Flutter Windows 界面。用本机网关验证浏览到委托、成交和持仓的核心流程，实测加载、空数据、断网和暂停等状态。先跑通 Windows 构建和运行，再移植 Android。
4. 部署与后续验证。测试中断恢复和安装包。盘中测量行情新鲜度和稳定性后再决定实时模式。
