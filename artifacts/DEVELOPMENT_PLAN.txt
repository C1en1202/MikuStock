MikuStock 开发规划（2026-11-20 实测后修订）

一、结论与证据
测试环境：Windows / Python 3.12 / AKShare 1.20.65。
东方财富快照、报价、分钟、日线在系统代理与 requests 直连对照中均未取得有效数据；出现 TLS 错误和 JSON 解析错误，不能据此判定所有用户网络均不可用。
腾讯全市场快照分页到 offset=1400 时失败，不能将部分分页视为完整成功。
新浪全市场快照远端断开。
腾讯平安银行日线返回 15 行，约 7.70 秒；新浪同股日线返回 15 行，约 12.42 秒。最近三日 OHLC 一致，成交量和成交额存在精度差异。
腾讯贵州茅台日线首次返回 15 行，约 11.84 秒；复测在辅助域名 web.ifzq.gtimg.cn 请求时超时。首次成功结果见本次执行记录，最新 JSON 保存的是复测结果。
新浪平安银行 1 分钟线连续两次返回 1970 行，约 6.91 秒与 3.59 秒，末条为 2026-11-20 15:00。
分钟样本范围 2026-11-10 13:53 至 2026-11-20 15:00，首日不是完整交易日。复测通过价格数值、正值、OHLC 关系、时间有效性、排序与唯一性检查。
测试发生在收盘后，未验证盘中延迟、连续稳定性、盘口可用性，也未验证全市场和各板块覆盖。
直连对照仅在测试进程的 requests Session 中禁用代理，不改变系统代理；没有关闭 TLS 校验。

二、产品范围
目标为 Windows / Android、Material Design 3、虚拟资金的 A 股模拟交易程序。
暂定首版优先实现历史回放；待用户确定后固化此范围。盘中模拟保留独立模式，需通过交易时段测试后启用。
优先覆盖普通沪深主板股票；创业板、科创板、北交所、风险警示与特殊上市阶段按规则和数据覆盖验证逐步加入。
首版：股票目录与搜索、自选、日线/分钟图、回放控制、限价委托、撤单、持仓、资金流水、成交记录、资产曲线、本地持久化。
近期分钟数据按需缓存；不承诺免费接口能提供完整长期 1 分钟历史。回放只使用完整且经过验证的交易时段。

三、数据方案
日线：腾讯候选主源，新浪候选备用；鉴于腾讯复测超时，必须有缓存、超时和有限退避。
分钟：新浪候选主源。东方财富适配器保持禁用或实验状态。
股票目录、交易日历、证券状态、涨跌停价、复权因子、除权除息事件尚未验证，是完整 A 股模拟的后续必需项。
资金成交使用未复权价；图表可选复权显示，必须与成交价格区分。
统一代码、日期时区、成交量单位和十进制精度。当前样本有字符串数字与浮点金额，需规范化并保留源精度，不能因两个源数值接近而假定完全等价。
每条记录保留来源、行情时间、抓取时间、周期与复权方式。不得静默混合源、前向填充缺失成交数据或用旧行情撮合。
避免每个客户端重复全市场轮询。超时重试应有限且有退避；明确限流时停止连续重试。

四、架构和界面
Flutter/Dart 客户端；Python 行情网关集中运行 AKShare；SQLite 缓存行情与本地交易数据。
Android 连接可访问的网关，不在 Android 安装包中嵌入 Python。Windows 原型可运行本机网关。部署位置与公网访问方式待确定。
交易引擎采用独立 Dart 模块，行情网关只负责数据获取与清洗。单机回放账户本地保存；跨端账户同步暂缓。
界面层、应用层、领域层、数据层分离，避免行情库 API 名称渗入业务页面。
Android 小窗口底部导航与单栏详情，Windows 大窗口侧边导航与多栏列表/详情；按窗口宽度切换。
Material Design 3 主题、明暗模式、统一组件与间距、对齐数字、独立涨跌色；支持键盘、鼠标与触控。

五、回放与撮合
行情显示与撮合遵守回放时钟；不得让界面预先显示未来 K 线或用当前 bar 尚未发生的高低价触发成交。
首版采用下一根完整分钟 bar 的开盘价模型：买入开盘价不高于限价、卖出开盘价不低于限价时才允许模拟成交，否则继续等待。成交时间和价格须对应该 bar 的开盘事件。
此模型不重建分钟内路径、真实排队和冲击；成交量限制、部分成交与零成交 bar 处理需在引擎规范中明确。
分钟缺失、停牌或关键规则未知时暂停相关标的撮合，不以日线高低价代替分钟路径。
资金冻结应包含预估费用；持仓需区分总量、可卖数量、冻结数量及按交易日的买入批次。
交易日历、交易时段、结算约束、申报数量、撤单限制、涨跌幅和费用按板块及生效日配置，并在实现前核查交易所与相关官方来源。不要把全部 A 股硬编码为同一规则。
跨除权除息日期的回放需处理现金与持股变动；未实现前阻止跨越这类事件。
订单、成交、持仓、资金流水更新必须原子化，事件幂等，重启恢复后不得重复成交。

六、实施与验收
阶段 1：数据验证与网关。补测股票目录/日历/状态；验证沪深代表股票、完整交易日分钟数据、故障缓存、单位转换和有限重试。产出规范化数据契约。
阶段 2：交易引擎。确定规则依据、订单状态机、资金冻结、持仓批次、费用和回放时钟。用资金守恒、无未来数据、撤单解冻和重复事件测试验收。
阶段 3：双端界面。实现行情到委托、成交、持仓的完整流程，以及缺失行情与暂停撮合状态。
阶段 4：持久化与打包。验证中断恢复、Windows 与 Android 安装和核心流程；平台未实机验证时不得宣称通过。
阶段 5：盘中行情验证。交易时段测量来源时间、接收时间、更新间隔、失效率和报价覆盖，结果合格后决定实时模式方案。

七、复现
基础东方财富：.\.venv\Scripts\python.exe scripts\probe_akshare.py
requests 直连对照：追加 --direct
腾讯/新浪对照：追加 --fallback --direct
新浪分钟与腾讯沪市日线复测：追加 --verify --direct
每次运行会覆盖对应 JSON；长期观测前应增加按时间保存的结果文件。
